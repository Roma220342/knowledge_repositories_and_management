# Порівняння моделей embeddings (HNSW)
> **Відхилення від завдання:** у середовищі виконання немає доступу до HuggingFace, тому замість multilingual-e5 порівняно дві щільні моделі LSA (TF-IDF + SVD, 128d): `lsa-word` (стеми + біграми) і `lsa-char` (символьні 3–5-грами). Адаптер `STEmbedder` для e5 є в src/index.py (не запускався тут).

Параметри HNSW: M=32, efConstruction=80, efSearch=64, метрика — inner product на нормованих векторах; 210 векторів; пам'ять векторів 105.0 КБ.

| Модель | час побудови, с | затримка пошуку (сер./p95), мс | recall@5 (20 запитів) | MRR |
|---|---|---|---|---|
| lsa-word | 0.104 | 1.107 / 1.193 | 0.908 | 0.864 |
| lsa-char | 0.448 | 2.295 / 2.414 | 0.858 | 0.807 |

Вплив параметрів (lsa-char): M=16, efSearch=16: recall@5=0.858, 2.393 мс; M=16, efSearch=64: recall@5=0.858, 2.284 мс; M=32, efSearch=16: recall@5=0.858, 2.325 мс; M=32, efSearch=64: recall@5=0.858, 2.303 мс; M=32, efSearch=128: recall@5=0.858, 2.311 мс

**Мова:** українська морфологічно багата. `lsa-word` із префіксним стемером точніша на 20 запитах; англомовні запити (3 шт.) обидві моделі не знаходять (recall@5 = 0.0), бо кросмовних знань немає — для двомовних корпусів потрібна multilingual-модель.

## Процедура оновлення
Upsert: новий вектор додається в HNSW, старий вектор позначається tombstone і відфільтровується під час пошуку; delete — tombstone; compact — перебудова графа без «мертвих» вузлів. Словник моделі фіксований: при значному дрейфі лексики потрібне перенавчання (refit).

| Документ | upsert, мс | нова версія top-1 | стара версія зникла | видалено фрагментів | витік у топ-10 після delete |
|---|---|---|---|---|---|
| D03 | 4.37 | True | True | 10 | 0 |
| D07 | 2.4 | True | True | 10 | 0 |
| D12 | 2.29 | True | True | 10 | 0 |
| D15 | 2.84 | True | True | 10 | 0 |
| D20 | 2.31 | True | True | 10 | 0 |

Живих фрагментів: 210 → 160; розмір індексу до/після compact: 215 → 160.
