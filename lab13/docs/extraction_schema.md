# Схема витягу та інструкція розмітки
Сутності (6): Person, Position, Department, Skill, Course (+ ідентифікатори з ЛР 9). Відношення (6): HAS_POSITION(Person,Position), WORKS_IN(Person,Department), HAS_SKILL(Person,Skill), COMPLETED(Person,Course), REPORTS_TO(Person,Person), REQUIRES_SKILL(Position,Skill).
Приклад/контрприклад: «Іван Шевчук завершив курс «Python Basics»» → COMPLETED; «Іван Шевчук планує пройти курс…» → не твердження.
Правила: 1) розмічати лише явні твердження; 2) заперечення, плани, гіпотези — не твердження; 3) займенники (Він/Вона/У нього) розв'язувати до останнього названого співробітника; 4) назва курсу — Course, навіть якщо містить назву навички; 5) прізвище без імені — та сама сутність; 6) кожне твердження має evidence-речення; 7) повтор одного факту в документі — одне твердження.
Граничні випадки: «Python-розробник» — Position (не Skill); «програмування на Python» — Skill python; «У нього…» без попередника — пропустити.
JSON виходу: {"claims":[{"subject":str,"relation":enum,"object":str,"evidence":str}]}. Нормалізація: звести до id закритого словника (ЛР 9), регістр/відмінок ігнорувати.
Пілот і уточнення: див. звіт (розділ Результат 1).
